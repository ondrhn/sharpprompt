# Measurements, v0.1.0

Date: 8 October 2026. Claude Code 2.1.293. Session model: the account's default (sharpprompt 0.1.0 did not record which). Effort: medium.
Two interactive sessions, 19 typed prompts, 8 of them rewritten. That is a small sample: read the numbers as a first look, not as evidence.

Tokens per rough prompt, from `/sharp stats` in the second session (n=5): about 2,531 input not from cache, 64,145 read from the prompt cache, 227 output. The fork reads the whole conversation again; that session's conversation was about 60k tokens.

Where the rewrite time goes: the fork runs on the session's model at the session's effort setting, and Claude Code's fork takes no effort or token limit. A rewrite of about 45 words came with about 227 output tokens on average, so most of the time is the model thinking, not reading.

## How it was measured

The gate: `tests/gate.bench.test.ts`, run by `claude plugin test .`. It calls `gate()` and the answer check (`endsWithQuestion()` on a 2,000-word reply ending in a question and a code block) 100,000 times in batches of 100 and prints the mean and the p99 of the per-call batch averages. Three runs on an AMD Ryzen 5 5600X under WSL2: mean 17.1 to 17.5 us, p99 33.5 to 37.8 us. On your machine:

```sh
claude plugin test . 2>&1 | grep "gate bench"
```

Everything else: real interactive sessions driven through tmux (`claude --plugin-dir .`), with timings read from `/sharp status`, which reports the plugin's own clock readings for the classifier and the rewrite. The second session ran in a small throwaway Python project, because auto mode was on and the prompts asked for code changes. "Enter to box" is the time from pressing Enter to the drop notice on screen, polled every 250 ms, including a 0.4 s send delay of the test driver.

## What this run found

- Prompts 8 and 9 were meant to be rough and were labelled clear. The classifier labels changed after this run ("clear and specific" / "rough: vague or missing what to deliver"); the next measurement shows whether that helps.
- Two rewrites (6 and 7) added "a new test" to the done criteria though nobody asked for one. The rule now says to use a check that already exists.
- The answer check missed a question followed by a code block. Fixed, with tests.
