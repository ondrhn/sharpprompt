# Benchmark v2, hidden spec with a new ask instruction

[Deney A](bench-2026-10-09-v2-helper-sonnet.md) showed that a stronger helper did not fix the rewrite's questions, so here the instruction changed instead. The new text in `hooks/rewrite.ts` (`ASK`) tells the rewrite to ask for the value the user knows (a separator, a threshold, a count, a currency, a format), to ask for another team's or tool's expectation when the draft defers to it, and to offer candidate values as options, not ways of supplying them. It also says this overrides the rule about taking the most direct reading. The helper stayed Haiku, as in the v2 runs.

With the new text the rewritten arm passed 7 of 10 hidden-spec checks on both models, up from 5 with the old text. The target was 8; it was not reached. With the cases the oracle leaked on or answered wrongly left out, it is 5 of 6 on Sonnet 5.5 (old 4) and 6 of 8 on Fable 5.1 (old 4).

Run on 9 October 2026, Claude Code 2.1.295, one repeat, the 10 hidden-spec cases, rewritten arm only. Rewrites: [rewrites/sonnet-v2-ask2](../bench/rewrites/sonnet-v2-ask2) and [rewrites/fable-v2-ask2](../bench/rewrites/fable-v2-ask2), helper Haiku, oracle Sonnet 5.5 with the no-naming rule. Runs: [Sonnet 5.5](../bench/runs/2026-10-09-v2-ask2-claude-sonnet-5-5.jsonl), [Fable 5.1](../bench/runs/2026-10-09-v2-ask2-claude-fable-5-1.jsonl). The raw arm and the old-text arm are the v2 runs ([Sonnet](bench-2026-10-09-v2-sonnet-5-5.md), [Fable](bench-2026-10-09-v2-fable-5-1.md)); the Sonnet-helper arm is Deney A.

## Where the new text still lost

- spec-top3-other (both): it asked how many and got 3, but nobody asked about the Other line, so the model kept three and dropped the rest. The instruction says to ask both when two values are missing; the helper did not see the Other line as one.
- spec-csv-separator (Sonnet): the separator question got "Semicolon", and a second question asked for the date format, which the user had not thought about; the oracle said it did not know. The model added a `delimiter` argument, left the default at a comma and said it was waiting for the date format. The second question cost the case.
- spec-refunds (Sonnet): asked how negative amounts should be stored, with "Keep the minus sign" and "Positive, marked as debit" as options. The oracle picked "Keep the minus sign", which is not what the user meant (refunds kept apart). A wrong oracle answer; we count the case as tainted.
- spec-refunds (Fable): no question. The rewrite says "Take the most direct reading of 'properly' and state the assumption you made", the Fable rule the new sentence was meant to override.
- spec-near-75 (Fable): asked the share, got 75%, and the model moved the threshold to 0.75 with the strict `>` it had, so 75 of 100 does not warn. The boundary problem from the Sonnet v2 run, now on Fable.

## Oracle leaks

The audit flags 3 cases in each set (near-75, round-005, column-order on Fable; sort-amount, round-005, column-order on Sonnet). Read by hand, all six answer the question asked with a value that none of the options had ("75% of the budget", "nearest 5 cents", "amount, date, category, name"), so none is a leak. The one tainted answer is the wrong pick on Sonnet refunds, which a text audit cannot see.

## Blind judge

Sonnet 5.5 as judge, raw answers from the v2 runs judged again against the new rewritten ones.

- Sonnet 5.5: rewritten 8, raw 2, tie 0, p = 0.11; scores raw 2.50, rewritten 3.70.
- Fable 5.1: rewritten 6, raw 3, tie 0, one pairwise verdict lost to a JSON error (spec-top3-other), p = 0.51; scores raw 2.50, rewritten 3.90.

## Limits

- 10 cases, one repeat, rewritten arm only; a case is 10 points.
- We wrote the new instruction after reading where the old one failed, on these same 10 cases. The gain is in-sample. It needs other cases before it counts.
- The oracle answers like a user who knows exactly what they want. A real user asked "What field delimiter?" may not know either.
- The second, unasked-for question on csv-separator shows the cost of asking more: a question the user cannot answer can stall the work.
