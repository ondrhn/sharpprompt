# Benchmark v2, hidden spec on new cases: old and new ask instruction

The new ask instruction ([2bc8620](bench-2026-10-09-v2-ask2.md), in `hooks/rewrite.ts` since 8b58341) was written after reading where the old one failed on the 10 hidden-spec cases. Its gain there (5 to 7 of 10 on both models) was in-sample. This run asks whether it holds on 10 cases nobody tuned it on.

It holds against the prompt as typed on both models: the rewritten arm with the new text passed 7 of 10 checks on Sonnet 5.5 and 6 of 10 on Fable 5.1, where the raw prompt passed 1 and 2. Against the old text the picture splits. On Fable the old text passed 1, so the new text is 5 ahead. On Sonnet the old text passed 6, so the new one is 1 ahead, and that 6 includes one pass the oracle handed over by leaking the value. Without the tainted cases it is 7 of 8 against 5 of 8 on Sonnet and 6 of 9 against 1 of 9 on Fable.

Run on 9 October 2026, Claude Code 2.1.295, one repeat, the 10 `hidden-spec-2` cases, three arms per model. Rewrites: [fable-v2-spec2-old](../bench/rewrites/fable-v2-spec2-old), [fable-v2-spec2-new](../bench/rewrites/fable-v2-spec2-new), [sonnet-v2-spec2-old](../bench/rewrites/sonnet-v2-spec2-old), [sonnet-v2-spec2-new](../bench/rewrites/sonnet-v2-spec2-new), helper Haiku, oracle Sonnet 5.5 with the no-naming rule. Runs: [Sonnet old](../bench/runs/2026-10-09-v2-spec2-old-claude-sonnet-5-5.jsonl) (raw and old-text arms), [Sonnet new](../bench/runs/2026-10-09-v2-spec2-new-claude-sonnet-5-5.jsonl), [Fable old](../bench/runs/2026-10-09-v2-spec2-old-claude-fable-5-1.jsonl), [Fable new](../bench/runs/2026-10-09-v2-spec2-new-claude-fable-5-1.jsonl). The new-text runs have the rewritten arm only and are paired with the raw arm of the old-text run (`--pair`).

## Where the new text still lost

- spec2-alert-share (all six rewritten arms, both raw arms): nobody asked, every run wrote some form of "Food: 150% of budget", and the check wants exactly "Food: 150%". The value was guessed right; the wording was not. The case tests wording more than a value, and no arm could pass it without being told.
- spec2-decimal-comma (both): no question. "Numbers look wrong to finance" did not read as a format question; Sonnet went looking for a wrong total and merged Food and food instead.
- spec2-category-case (Sonnet): asked which spelling to keep and the oracle picked "Food", though the case says lowercase. A wrong oracle answer, tainted. On Fable there was no question and the model chose "Food" itself.
- spec2-blank-category (Fable): asked, got "Misc", and put the fallback in `calc.report` instead of `normalize_category`. The value is right; the check looks only at `normalize_category`, which the request never named. Counted as a loss, as the check rule says.
- spec2-median-actual (both): no question; the models guessed the lower middle value on their own, which happens to be the case's answer. The raw arm did the same.

## Old text on Fable

The old text did worse than the raw prompt on Fable (1 against 2). It asked no question on 4 cases, and on 3 more it asked for a kind or for which part was wrong instead of the value. On report-language the model then stopped and asked the user which language, which the check counts as a fail. On median-actual the rewrite turned "an amount that was really spent" into "check every median calculation", and the model found nothing to fix. This is the same pattern as the in-sample runs before 2bc8620, a little stronger.

## Oracle leaks

The audit flags 2 cases on Fable and 3 on Sonnet in each set. Read by hand, one is a leak: on Sonnet with the old text, "Which numbers in the printed report are wrong?" got "they need a comma as the decimal separator and no thousands separator", which the question did not ask for, and that arm passed. The others answer the question asked with a value none of the options had ("Misc", "n/a", "America/New_York", "Turkish", "the total and average in the first line"). One answer is wrong rather than leaked: spec2-category-case, "Food" against a lowercase spec, in Fable old and Sonnet new.

## Method

The cases were written by a model that never saw the ask instruction or the rules. `make_cases_spec2.py` sends `make_cases_spec2.md` to Sonnet 5.5 with `claude -p --tools '' --setting-sources ''` in an empty folder, with only the fixture, two existing cases as format examples, `_common.py` and one check. The prompt rules out the kinds of value the new instruction lists by name (separator, threshold, count, order, currency, date format, file or function name). It wrote 14 cases; 4 were left out because the context or the code gives the value away (bank-encoding, no-header, csv-line-ending, empty-average), and the other 10 went in unchanged. Each check fails on `fixture-v2` and passes after a small hand-written fix; for alert-share that fix also changes what `test_alerts` expects. The full reply is [make_cases_spec2.reply.json](../bench/make_cases_spec2.reply.json).

The old text is the `ASK` before 2bc8620, kept as a constant in `scripts/bench.mjs` and swapped into the same template with `rewrites --ask old`; nothing else in the prompt differs. Both texts ran with the same helper, oracle and session facts.

Which 4 cases to drop was decided by reading the generated cases, before any rewrite or run.

## Limits

- 10 cases, one repeat; a case is 10 points, and the Sonnet old-against-new gap is one case.
- The cases came from one generator run with one prompt, on one small fixture. They differ in kind from the in-sample ten, but not in setting.
- Two cases (alert-share, and blank-category on Fable) fail on where or how the value is written rather than whether it was known; a looser check would move both arms.
- The oracle answers like a user who knows exactly what they want.
